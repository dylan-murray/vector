# Vector's CI/CD System (GitHub Actions)

Vector leverages GitHub Actions for its Continuous Integration and Continuous Deployment (CI/CD) processes. This system automates testing, building, and releasing Vector across various platforms and architectures.

## Core Principles

-   **Automation**: Minimize manual intervention for repetitive tasks.
-   **Reproducibility**: Ensure builds and tests are consistent across environments.
-   **Efficiency**: Optimize workflows for speed and resource usage.
-   **Observability**: Provide clear status and logs for all CI/CD runs.

## Key Workflows

### `build-test-runner.yml` — Build Test Runner Image

-   **Purpose**: Builds the Docker image used for integration and end-to-end tests.
-   **Trigger**: Called by other workflows (e.g., `integration.yml`, `ci-integration-review.yml`).
-   **Permissions**: Requires `contents: read` and `packages: write` (to push to GHCR).
-   **Steps**: Checks out code, sets up `vdev`, logs into GHCR, builds the `vector-test-runner` image with `vdev int build`, tags it with the commit SHA, and pushes it to `ghcr.io/vectordotdev/vector/test-runner`.

### `changes.yml` — Identify Changes

-   **Purpose**: Detects file changes between base and head refs to conditionally run downstream jobs.
-   **Trigger**: Called by other workflows (e.g., `integration.yml`, `master_merge_queue.yml`).
-   **Outputs**: Provides boolean flags indicating changes in various categories (e.g., `source`, `dependencies`, `k8s`, `website_only`, specific integration tests).
-   **Mechanism**: Uses `dorny/paths-filter` action with a `int_test_filters.yaml` generated by `vdev int ci-paths` for fine-grained detection of integration test-specific changes.

### `ci-integration-review.yml` — CI Integration Review Trigger

-   **Purpose**: Allows maintainers to trigger specific integration/E2E tests via PR review comments (e.g., `/ci-run-integration-amqp`, `/ci-run-all`).
-   **Trigger**: `pull_request_review` event (on `submitted`).
-   **Permissions**: Requires `statuses: write` to update commit status.
-   **Steps**: Validates reviewer membership, sets pending status, calls `build-test-runner.yml`, then conditionally runs matrix of integration/E2E tests based on comment content.

### `ci-review-trigger.yml` — CI Review Trigger

-   **Purpose**: Allows maintainers to trigger various non-integration CI jobs via PR review comments (e.g., `/ci-run-cli`, `/ci-run-deny`).
-   **Trigger**: `pull_request_review` event (on `submitted`).
-   **Permissions**: Requires `statuses: write`.
-   **Steps**: Validates reviewer membership, then conditionally calls reusable workflows for CLI, deny, component features, cross-compilation, unit tests, etc.

### `cleanup-ghcr-images.yml` — Cleanup Untagged GHCR Images

-   **Purpose**: Prevents unlimited storage growth in GitHub Container Registry.
-   **Trigger**: Weekly schedule (`cron: '0 2 * * 0'`) and `workflow_dispatch`.
-   **Actions**: Deletes untagged `vector` images and old `test-runner` images (keeping 50 most recent).

### `component_features.yml` — Component Features - Linux

-   **Purpose**: Validates that all component features compile correctly.
-   **Trigger**: Scheduled (Monday 10:00 UTC), `workflow_dispatch`, `workflow_call`.
-   **Steps**: Checks out code, frees disk space, sets up Rust toolchain, and runs `make check-component-features`.

### `coverage.yml` — Code Coverage

-   **Purpose**: Generates and uploads code coverage reports to Datadog.
-   **Trigger**: `push` to `master`, `workflow_dispatch`.
-   **Steps**: Checks out code, sets up Rust toolchain with `cargo-llvm-cov`, generates coverage with `cargo llvm-cov nextest`, and uploads `lcov.info` to Datadog.

### `cross.yml` — Cross

-   **Purpose**: Builds Vector for various Linux cross-compilation targets (e.g., `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-gnu`).
-   **Trigger**: `workflow_call`.
-   **Strategy**: Uses a matrix for different targets.
-   **Steps**: Checks out code, caches Cargo, installs `cross`, builds with `make cross-build-<target>`, and uploads artifacts.
